# Добавление устройств

## Новый модуль

1. Реализуйте `IBatteryDriver` в отдельном C#-файле.
2. `Id` должен быть постоянным уникальным именем протокола.
3. `Matches` должен проверять VID/PID, usage page, usage и размеры отчётов. Не отправляйте неизвестные команды всем HID-устройствам подряд.
4. `Describe` возвращает название, `DeviceKind` и тип подключения без опроса устройства.
5. `Read` выполняет только известные запросы состояния с ограниченным временем ожидания. Возвращайте `Percent=null`, если достоверного показания нет. При успешном чтении задавайте `Time=DateTime.Now`, `Percent` в диапазоне 0–100 и состояние. `Charging=true` допустимо только при подтверждённой зарядке.
6. Зарегистрируйте модуль в `Devices.monitor` и добавьте файл в `build.ps1` и `test.ps1`.
7. Добавьте реальные примеры ответов и отрицательные тесты в `Tests.cs`. Проверьте сон, отключение приёмника, зарядку и повторное подключение.
8. Обновите таблицу поддержки: отмечайте реальные аппаратные проверки отдельно от экспериментальной реализации.

Модуль не должен создавать окна, уведомления или изменять настройки устройств. Идентичность экземпляров и последнее показание ведёт `BatteryMonitor`, оповещения и отображение — интерфейс. Список из одного опроса используется на всех мониторах.

## Запрос поддержки

Создайте GitHub Issue с моделью, типом подключения, VID/PID, версией Windows, ссылкой на официальный софт и результатом `PeripheralBatteryMonitor.exe --diagnose report.txt`. Отчёт содержит сведения о подключённых HID-устройствах; просмотрите его перед публикацией.

Если протокол неизвестен, потребуется запись обмена официальной программы с устройством и помощь владельца в проверке. Не публикуйте токены, личные данные или закрытые файлы производителя.

## Проверки

Для стандартного API Windows, не связанного с HID, реализуйте `IBatterySource` и зарегистрируйте источник в `Devices.sources`. Источник отвечает за стабильные в рамках API идентификаторы и явно устаревшие показания при отключении. Если API сообщает только дискретные уровни батареи, используйте `Reading.Level`, не вычисляйте вымышленные проценты. `XInputSource` служит примером и принимает функцию опроса для тестирования без оборудования.

HID-модуль может реализовать `IBatteryPollingPolicy`, чтобы ограничить частоту фоновых запросов. Ручное обновление и обнаруженное переподключение обходят этот интервал; при пропуске запроса время последнего замера не изменяется.

```powershell
.\test.ps1
.\build.ps1
```

Тесты не обращаются к оборудованию. Они проверяют протоколы и реестр: несколько устройств, дубликаты перечисления, одинаковые модели, неизвестные устройства, ошибки драйвера, устаревание, отключение и повторное подключение.

Для нескольких альтернативных HID-коллекций одного приёмника используйте IBatteryIdentityProvider со стабильным физическим ключом. Реестр попробует следующие коллекции при неудаче и остановится после достоверного ответа; добавьте тест такого перебора. IRequireBatteryReading скрывает новые устройства до первого корректного показания, а IBatteryPollingPolicy ограничивает также повторные запросы молчащих приёмников.
